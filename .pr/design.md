# Issue #62 Design: Intelligent Scanning for Project-Scoped Boards

## Problem Statement

Project-scoped boards now have an explicit `scope`, `overview_item`, and `mission`, but `lxa board scan` still treats those boards as unsupported: it prints the overview item and asks users to add related items manually. Users need the scanner to discover issues and pull requests that are mechanically connected to existing board items, evaluate whether each candidate belongs to the board's project mission, explain every decision, and still allow manual overrides through `lxa board add-item`.

The full feature has several parts: reference extraction, candidate discovery, mission-based evaluation, board updates, and rich scan reporting. This implementation focuses on the first milestone only so the later discovery and evaluation layers have a well-tested, reusable parser for GitHub references and local reference context.

## Proposed Solution

Build a dedicated `src/board/references.py` module that parses GitHub issue and pull request references from markdown/text bodies. The module will expose typed dataclasses for normalized references and contextual matches:

- `GitHubRef`: normalized owner/repo/number plus optional reference type.
- `ReferenceContext`: a reference plus the source board item, surrounding text, and where the reference was found.
- `parse_github_refs()`: extracts references from supported syntaxes while resolving shorthand references using source/default repository context.
- `extract_reference_contexts()`: returns deduplicated contextual references with nearby text for scan output and future LLM evaluation.

This keeps milestone 1 independent from GitHub API access, LLM calls, and board mutation. Later milestones can consume the parser to discover outbound candidates from item bodies/comments and to display transparent rationale context.

## Implementation Plan With Milestones

### Milestone 1: Reference Parsing Infrastructure

- Add `src/board/references.py` with `GitHubRef`, `ReferenceContext`, `parse_github_refs()`, and context extraction helpers.
- Support these reference syntaxes:
  - Full GitHub issue/PR URLs: `https://github.com/owner/repo/issues/123`, `https://github.com/owner/repo/pull/456`.
  - Cross-repo shorthand: `owner/repo#123`.
  - Same-owner shorthand: `repo#123` resolved with `default_owner` or a source item repo.
  - Same-repo shorthand: `#123` resolved with `default_repo` or a source item repo.
- Deduplicate repeated references while preserving first-seen order.
- Extract compact surrounding text for later reporting/LLM prompts.
- Add focused unit tests for URL parsing, shorthand parsing, context extraction, deduplication, invalid/unresolved references, and false positives.

### Milestone 2: Candidate Discovery

- Add discovery logic that fetches board item bodies/comments and parses outbound references.
- Add inbound discovery through GitHub search for items mentioning current board items.
- Batch and deduplicate API calls, skip inaccessible/deleted items with warnings, and avoid circular traversal.

### Milestone 3: Mission-Based Evaluation

- Add LLM-backed scope evaluation using the board `mission` and reference contexts.
- Parse deterministic response fields into `ScopeDecision` objects.
- Add safeguards for malformed model responses and concise fallback rationales.

### Milestone 4: Project Scan Integration

- Replace the project-scoped scan placeholder with full discovery/evaluation/update orchestration.
- Add `--dry-run` behavior for project-scoped scans.
- Add in-scope items to Triage and report out-of-scope items with rationale and manual override instructions.
